# 各阶段退出标准判定规则

> 本节汇总 opc-starter-kit 四个阶段的退出标准（绿队关卡），包含判定逻辑和边界情况处理。

---

## 退出标准总览

| 阶段 | 绿队关卡（必须满足） | 红队关卡（必须通过） | 最低产物要求 |
|------|---------------------|---------------------|-------------|
| 想法 | ≥5 次真实客户对话 + 竞品格局完成 + 趋势分析完成 + 轻量原型5人试用 | 三维度反方论证已回应 | 6 个 doc + 通关报告 |
| MVP | Sean Ellis >40% + 2/3 信号 | 假阳性已排查 + 多框架攻击已回应 | 4 个 doc + 通关报告 |
| 发布 | 增长可重复 + 产品稳固 + 运营独立 | 疲惫创始人质疑已回应 | 3 个 doc + 通关报告 |
| 规模化 | 组织可持续 + GTM引擎就位 + 护城河存在 | 护城河压力测试已回应 | 5 个 doc + 通关报告 |

---

## 阶段一：想法阶段退出标准

### 条件 1：客户对话 ≥ 5 次

**判定规则**：
- 必须是真实人类的对话，不能用 AI 模拟对话替代
- 每 5 次对话为一批，每批结束后执行双清单对比
- 如果多批对话后仍无法确认需求 → 可能是问题不存在或问题不值得做

**边界情况**：
- 用户行业经验很深（如从业15年），说自己"就是目标用户" → 不替代，仍需外部验证
- 无法找到目标用户进行对话 → 这是红队攻击点（找不到用户=需求可能不真实）
- B2B 用户难以触达 → 调整对话标准为"行业专家访谈 + 二手研究"

### 条件 2：竞品格局分析完成

**判定规则**：
- 四层格局（直接/间接/潜在收购方/相邻玩家）至少各有 1 个代表性竞品
- 每层代表写了"为什么他们会赢"的论证
- 差异化空间被识别且有逻辑支撑

### 条件 3：红队关卡通过

**判定规则**：
- 三个维度（不值得做公司/差异化不成立/不会付费）的每个论点都已被回应
- 创始人的回应不是"我觉得"而是有逻辑和证据支撑

### 条件 4：趋势分析完成

**判定规则**：
- 识别了至少3个可能在未来两年影响市场的外部趋势（监管/技术/人口）
- 每个趋势已判断为顺风或逆风，且有逻辑支撑
- TAM/SAM/SOM 模型已构建，假设已压力测试

**边界情况**：
- 市场过于新兴，趋势数据匮乏 → 用类比市场替代，标注置信度
- 趋势全为逆风 → 这是红队攻击点，需给出应对策略

### 条件 5：轻量原型通过5人试用

**判定规则**：
- 原型聚焦于方案依赖的那一个核心交互
- 5个已验证目标画像的人已试用
- 反馈支持继续（不需要完美，但至少无明显反对信号）

**边界情况**：
- 硬件产品 → 低保真原型/手绘方案/3D渲染图替代可交互原型
- API/开发者工具 → 沙盒API/技术demo替代UI原型
- 咨询/服务 → 免费诊断会/试点项目替代

## 阶段二：MVP 阶段退出标准

### 条件 1：Sean Ellis 测试 > 40%

**判定规则**：
- 向活跃用户发送标准 Sean Ellis 问题："如果 [产品] 明天消失了，你的感受是？"
- "非常失望" 比例 > 40% 为通过
- 样本量至少 20-30 个有效回复

**边界情况**：
- 用户数不够 → 暂缓判定，先达到最低样本量
- 非 SaaS 项目 → 寻找等效信号（如硬件产品用"愿意推荐给同行"的比例）
- 用户过于同质化（都是朋友/朋友圈）→ 提示样本偏差风险

### 条件 2：2/3 信号确认

**三个信号**：
- 留存：用户在持续使用（不只是注册了）
- 付费：用户在用钱投票
- 推荐：用户在主动传播

**判定**：至少两个信号同时存在。

### 条件 3：假阳性已排查

**排查清单**：
- [ ] 注册但从未激活的用户比例？
- [ ] 付费一次后从未回来的用户比例？
- [ ] 初期用户来源是否带偏差（朋友/投资人关系/一次性流量峰）？
- [ ] 是否为"被推"（主动推广获取）多于"被拉"（自然增长）？

## 阶段三：发布阶段退出标准

### 条件 1：增长可重复

**判定规则**：
- CAC（获客成本）、LTV（用户生命周期价值）、回收周期均有数据
- 增长不由创始人个人关系驱动
- 至少一个可重复的获客渠道

### 条件 2：产品稳固

**判定规则**：
- 技术债审计完成，🔴 项（发布前必须修）已清零
- 没有已知的数据损失或重大安全风险
- 有基本的生产环境监控

### 条件 3：运营独立

**判定规则**：
- 创始人瓶颈审计完成
- 🔴 项（创始人不在就停）至少有一半已解除
- 关键运营流程的最低文档已产出

## 阶段四：规模化阶段退出标准

规模化阶段没有"完成"的概念，退出标准是持续性的：

### 持续条件 1：组织可持续
- 创始人减少投入时，核心业务不受影响
- 财务报告 / 合规 / 客户支持 / 合同管理有基本覆盖

### 持续条件 2：护城河可防守
- 护城河积分卡持续更新，无持续下降趋势
- 能清晰回答：5000万美元竞品入侵后，用户为什么留下？

### 持续条件 3：GTM引擎可运转
- 市场细分、信息架构、销售playbook 已产出
- 增长不依赖创始人个人销售
- 至少一个可重复的获客渠道在运转

### 持续条件 4：企业基础设施就位
- 技术文档、支持playbook、可观测性层已搭建
- 前3个理想客户的差距分析已完成
- 满足最苛刻客户的审查要求（SLA/合规/支持）

## 跳过环节的处理规则

### 允许跳过的情况
- 用户明确选择 `opc skip`（或 `opc 跳过当前环节`）
- 在以下场景中允许部分弹性：
  - 行业经验极深的创始人 → 客户对话数可协商降低，但不能为 0
  - 已有在运营产品的项目 → 可以从事后诊断模式进入

### 跳过的后果
1. 记录到 `decisions.md` 和 `risk_profile`
2. 后续阶段可能引用跳过记录："你在想法阶段跳过了X，现在Y缺乏基线数据，这是原因之一"
3. 跳过次数在仪表盘可见

### 不允许跳过的情况
- ❌ 红队关卡——任何阶段都不能跳过
- ❌ 安全审查——MVP 阶段的编码前安全提醒不能跳过
- ❌ 发布阶段安全合规升级——不能跳过
