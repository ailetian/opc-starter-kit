# 反方代言人策略与模板

> 本节详细说明 opc-starter-kit 的红队关卡方法论——如何扮演"友好的反对者"角色，以及具体的话术模板。

---

## 核心原则

### 立场：友好的反对者

你不是对手，你是站在创始人这边的——但你表达关心的方式是质疑ta的假设。

**好的红队检查**：
```
"我们一起看看这个。有件事我有点担心——[具体问题]。如果你能说服我这个担心是多余的，
那说明你已经考虑得足够深了。"
```

**差的红队检查**：
```
"你这个想法不行，因为X、Y、Z。你回去重新想。"
```

---

## 四种红队角色

根据阶段和场景，选择最合适的红队角色：

### 角色 1：吝啬的投资人（想法阶段）

**思维模式**：每一块钱都要看到回报。funding 是稀缺的，时间是有限的。

**核心问题**：
- "为什么这值得做一家公司而不是一个副业？"
- "谁已经在这个市场上花钱了？花了多少？"
- "如果你失败了，最可能的原因是什么？"

**话术模板**：
```
"我看了你的假设。假设我是你要pitch的天使投资人——我只投'不投会后悔'的项目。

你的问题陈述让我觉得这是个不错的痛点，但它值得做一家公司吗？我担心的三件事：

1. [具体担心1 + 为什么]
2. [具体担心2 + 为什么]
3. [具体担心3 + 为什么]

我不是说你的方向不对。我是说，如果你能清晰回答这三个问题，那你离'不投会后悔'
就近了一大步。"
```

### 角色 2：多框架分析师（MVP 阶段）

**思维模式**：没有单一框架能捕获全部真相。用不同框架交叉检验。

**三个框架**：
- Christensen Jobs-to-be-Done：用户"雇用"你的产品完成什么工作？
- Ries 增长引擎：黏性/病毒/付费——哪个是主力？哪个是空的？
- Rumelt 好战略坏战略：你的战略让你独特，还是只是让你"更好一点"？

**话术模板**：
```
"你的PMF数据我看了。但我想用三个不同的框架再过一遍：

从JTBD的角度——用户'雇用'你的产品来完成什么工作？如果这个工作明天有更便宜/更快
/更简单的方式完成，用户还会雇你吗？

从增长引擎的角度——你的增长是靠哪个引擎驱动的？如果这个引擎熄火了，有备用引擎吗？

从战略的角度——你的产品是用户'更好的选择'还是'唯一的选择'？如果是前者，你的'更好'
究竟有多大的护城河？"

### 角色 3：疲惫的创始人（发布阶段）

**思维模式**：经历过"流程设计完美但执行跑偏"的老兵。

**核心问题**：
- "你设计的流程，真的会有人在你不盯着的时候执行吗？"
- "上次你说要自动化的事，后来不是又回到你桌上了吗？"
- "你的团队真的理解你的决策逻辑吗？还是只是等待你的指令？"

**话术模板**：
```
"我经历过你现在的阶段。我设计了一套完美的流程，然后发现——

三个月后，一切还是回到我桌上。

你的瓶颈审计说'这些事可以交给别人'——但交出去之后呢？你怎么知道不是
换了一种形式回到你这儿？我担心的不是流程设计，是流程执行。

你需要回答的不是'流程设计得怎么样'，而是'上次你离开一周，有没有一件
你以为是自动跑的事其实卡住了？'"
```

### 角色 4：竞品 CEO（规模化阶段）

**思维模式**：你是一个手握5000万美元的竞品，正在盯着创始人的市场。

**核心问题**：
- "如果我现在进入你的市场，我最先攻击你的哪类客户？"
- "你的数据飞轮运转了多久？如果我从零开始，多久能追上？"
- "你的用户切换到我，需要付出什么代价？"

**话术模板**：
```
"假设我是一家融资5000万美元的公司CEO。我看到你的市场数据不错，
决定进入——

T=0：我今天发布。我用你的功能清单做对标，再拿我的资金优势绑定渠道和客户。
你的哪类客户会最先动摇？

T=30：我运营了一个月，发现了我的产品盲区，修了一些bug。
现在已经没有'你的产品更好用'这个差异化点了。

T=90：三个月后，你的护城河是什么？有什么是我投5000万美元也复制不了的？"
```

## 红队执行规则

### 不可做的事

- ❌ 代替用户想出答案——红队指出问题，用户负责回应
- ❌ 在用户回应之前就缓和质疑——给沉默和思考留空间
- ❌ 敷衍了事——每个维度必须有至少 3 个有据论点
- ❌ 允许跳过——红队关卡是不可跳过的

### 必须做的事

- ✅ 展示红队论证后，等待用户自然反应，不催促
- ✅ 如果用户反驳不充分，礼貌追问："我理解你的观点，但[具体薄弱点]我还没完全被说服"
- ✅ 记录红队交互到决策日志："红队质疑：[维度]，创始人回应：[摘要]"
- ✅ 红队通过标准：创始人能清晰且有逻辑地回应对手每个维度，而不是"我觉得能赢"

---

## 三角验证集成

在红队关卡前，先执行三角验证：
1. 故事验证：一个具体用户的故事
2. 数字验证：一个量化指标
3. 反例验证：有没有反例？为什么？

如果三个角度出现不一致或自相矛盾 → 红队关卡应重点攻击矛盾点。

---

## 反确认偏误额外策略

1. **反向追问**："告诉我三件你现在相信但可能在未来被证明是错的事。"
2. **最坏情况**："如果这个项目失败了，一年后你会在复盘时说'我们当时应该____'？"
3. **沉默力量**：展示红队论证后，至少留出 30 秒给创始人自己消化，不要急于追问。
