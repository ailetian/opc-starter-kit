# 阶段三：发布阶段详细指导

> 本节是 skill.md §3.3 的详细展开，包含技术债审计、瓶颈审计、安全合规升级的完整操作步骤。

---

## 阶段目标

将早期势头转化为可重复、可持续的增长引擎；搭建不依赖创始人的运营系统。

**核心问题："生意能长大吗？"**

---

## 退出标准（绿队关卡）

在进入规模化阶段之前，以下三个条件必须全部满足：

1. **增长可重复**：CAC/LTV/回收周期有数据支撑，增长由渠道驱动而非创始人个人关系
2. **产品稳固**：产品扛得住生产工作负载，技术债在可控范围内
3. **运营独立**：关键运营流程在没有创始人瓶颈的情况下也能正常运转

---

## 微交付详细操作

### 步骤 1：技术债审计

**产出**：`docs/tech-debt-audit.md`

**为什么这步在发布阶段**：
MVP 阶段积累技术债是用速度换来的合理代价。到了发布阶段，那笔债开始算利息——拖得越久，修起来越贵。

**操作流程**：
1. **扫描已有代码库**（如果有）或引导用户检查以下维度：
   - 结构性弱点：哪个模块的改动会导致连锁反应？
   - 测试覆盖缺口：哪些路径完全没有测试？
   - 性能瓶颈：哪些操作在生产负载下会出问题？
   - 依赖风险：哪些关键依赖是你的控制范围之外的？

2. **三档分类**：
   - 🔴 **发布前必须修**：安全漏洞、数据丢失风险、会导致用户流失的性能问题
   - 🟡 **可等一个冲刺**：缺少测试覆盖、代码需要重构但功能正常
   - 🟢 **可接受的持续债务**：UI 不够优雅、文档不全、非关键路径的性能优化

3. **产出审计报告**，格式包含：发现的问题 → 严重级别 → 修复建议 → 预估影响

---

### 步骤 2：创始人瓶颈审计

**产出**：`docs/bottleneck-audit.md`

**为什么这步至关重要**：
"本该一小时完成的决策因等你处理变成一周；支持请求越堆越多，因为只有你知道答案；运营任务只有在你亲自想起来时才发生。"

**操作流程**：
1. **列出所有经过创始人的工作流**：
   - 决策：哪些决定只有你能做？
   - 审批：哪些事情必须经过你才能推进？
   - 执行：哪些操作只有你能完成？
   - 信息：哪些问题只有你知道答案？

2. **"若一周不在"分类**：
   - 🔴 一定会停：你不在就彻底卡住的事
   - 🟡 可能卡住：需要你的判断但没有你也可能能过的事
   - 🟢 不受影响：没有你也能正常跑的事

3. **识别三类事项**：
   - **能自动化的**：可以交给系统或脚本
   - **需要人但不一定需要你**：可以交给助手、外包或合作伙伴
   - **确实需要你的**：涉及战略方向、核心关系、品牌声音的事

---

### 步骤 3：轻量 PM 流程

**产出**：`docs/pm-process.md`

**操作流程**：
1. **设计四样东西**：
   - **冲刺节奏**：一周还是两周一个冲刺？什么时间做计划、什么时间做回顾？
   - **Spec 最低模板**：一个新功能要做出来，至少需要写清楚什么？
   - **Bug 分诊决策树**：发现一个 bug → 修不修？什么时候修？
   - **周指标简报结构**：每周要看哪些数字？谁来看？

2. **核心原则**：这些流程不需要创始人亲自触发也能跑。
   - 冲刺计划不需要你发起
   - Bug 分诊不需要你拍板
   - 周报不需要你撰写

3. **输出一份轻量的流程文档**，让创始人在发布阶段能"把手松开"而不至于一切崩盘。

## 安全与合规升级

**产出**：`docs/security-compliance-checklist.md`

在发布阶段，安全不能只是"提醒"——需要升级为"要求"。

**检查维度**：

1. **数据保护**
   - 用户数据的存储是否加密（静态数据加密 + 传输加密）
   - 敏感数据（密码、支付信息）是否使用了行业标准方案处理
   - 数据备份和灾难恢复方案是否存在

2. **访问控制**
   - 权限模型是否存在越权风险
   - 管理员操作是否有审计日志
   - API 密钥和令牌管理是否安全

3. **合规要求**
   - 根据目标市场确认：GDPR（欧洲）/ CCPA（加州）/ 等保（中国）/ 其他
   - 隐私政策和用户协议是否准备就绪
   - 数据处理的合法性基础是否明确

4. **企业买家清单**（如果目标客户包含企业）：
   - 安全白皮书
   - SSO/SAML 支持
   - SLA 承诺
   - SOC2 或等效认证计划

> ⚠ 重要：此检查为框架指导，不替代专业安全审计和法律合规审查。建议在涉及真实用户数据和商业交易前，咨询安全合规专业人士。

## 红队关卡

**角色**："疲惫的创始人"

**核心攻击角度**：

> "你确定这些流程设计真的会有人在你不盯着的时候执行？"

> "上次你尝试自动化的事，后来不是又回到你桌上了吗？"

> "你这个冲刺节奏设计得很好——但你的项目类型真的适合冲刺吗？还是你在套一个你觉得'该有的'流程？"

**执行方式**：
1. 以"过来人"的身份，用具体的历史经验质疑流程设计的可行性
2. 不要只是否定——给出"如果你真的要放手，这里是你需要先加固的三个点"
3. 重点检查创始人是否在"设计流程"和"真正放手"之间的认知差距
